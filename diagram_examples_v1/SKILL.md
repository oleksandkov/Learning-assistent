# Скіл: Академічні блок-схеми за ГОСТ 19.701-90 та UML 2.5

Блок-схеми алгоритмів та UML-діаграми для курсових, дипломних і лабораторних робіт.
Єдине джерело генераторів: [`diagram_examples_v1/scripts`](diagram_examples_v1/scripts).

---

## ⛔ 4 залізні правила оформлення

1. **Жодних заголовків та рамок на зображенні.** Схема починається з першого вузла
   (`Початок` або `●`) і закінчується вузлом завершення (`Кінець` або `⦿`).
   Назви й номери рисунків живуть лише у тексті документа.
2. **Прозорий фон, біла заливка блоків.** Корінь SVG: `background: transparent`.
   Фігури: `fill: #ffffff` — щоб лінії, що проходять під блоками, не перетинали текст.
   Контури: `#000000`, `stroke-width: 1.5`.
3. **Суто українська мова.** `Початок`, `Кінець`, `Введення: a, b`, `Виведення: res`,
   `Так`, `Ні`, `сума = 0`, `i = 0, n - 1, 1`. Назви функцій — як у коді.
4. **Інженерна геометрія.** Усі злами строго під 90°, вхід/вихід по центру граней,
   наконечники — гострі трикутники 6–8 px на входах у блоки та на зворотному зв'язку.

## 🚀 Швидкий шлях: готові генератори

Не пиши SVG руками. Скористайся генераторами — вони вже рахують ширину тексту,
автоматично підганяють розміри блоків і вміють самоперевірку геометрії.

```bash
cd diagram_examples_v1

# 1. Перегенерувати всі 7 прикладів у SVG
python examples/build_all.py

# 2. Перевірити геометрію (exit code != 0 при помилці — це і є smoke-тест)
python examples/check_orthogonal.py

# 3. Рендер у PNG + JPEG (scale=3 — друкарська якість)
uv run --with cairosvg --with pillow python examples/export_raster.py
```

### `scripts/gost.py` — блок-схеми ГОСТ

```python
import sys, pathlib
sys.path.insert(0, str(pathlib.Path("scripts").resolve()))
from gost import Chart

c = Chart(width=520)
c.terminator("Початок", 160, 20)
c.io("Введення: a, b", 160, 96)      # паралелограм
c.process("max = a", 175, 200)        # прямокутник
c.condition("a > b", 190, 280, right=True)   # ромб, гілка "Так" праворуч
c.down(205, 318, 355)                 # ортогональний ліньєр зі стрілкою
pathlib.Path("out.svg").write_text(c.svg(), encoding="utf-8")
```

Типи блоків у `Chart`: `terminator`, `io`, `process`, `condition`, `prep` (шестикутник),
`subroutine` (подвійні риски), `connector` (коло), плюс `down()`, `right()`, `up()`, `label()`.

### `scripts/uml_class.py` — діаграма класів

```python
from uml_class import Klass, Diagram

d = Diagram()
base = Klass("GameState", 0, 0, ["+ board: List[List[Cell]]", "# running: bool"])
sub  = Klass("BFSState", 0, 260, ["+ queue: Deque"], methods=["+ step() -> None"])
sub.inherits(base)            # або .implements(...) для інтерфейсу
d.add(base, sub)
d.svg()
```

### Чому `check_orthogonal.py` — обов'язковий крок

Він ловить реальні баги геометрії: діагональні дроти у блок-схемі, вершини дротів
всередині блоку, перекриття блоків. Діагоналі в діаграмі класів легітимні, тому
правила ортогональності до неї не застосовуються. `export_raster.py` не запускати
без успішної перевірки — інакше просто рахуватимеш візually биту схему.

## 🎨 Варіант для coursework: draw.io

Коли схема йде в курсову/дипломну, користувач часто просить саме **draw.io**.
Генератори вище — для швидких ескізів і Markdown; фінальні рисунки для роботи
збираються в [diagrams.net](https://app.diagrams.net/?locale=uk) і експортуються в PNG.

### Обов'язкові властивості стилів draw.io

| Властивість | Значення |
| :--- | :--- |
| `strokeColor` / `fillColor` | `#000000` / `#FFFFFF` |
| `strokeWidth` | `1.5` |
| `fontFamily` | `Times New Roman` (ГОСТ) або `Helvetica` (UML) |
| `rounded` | `0` для прямокутників |

### ⚠️ Паралелограм draw.io — відома пастка

```xml
✅ shape=parallelogram;perimeter=none;whiteSpace=wrap;html=1;spacingLeft=28;spacingRight=28
❌ shape=parallelogram;perimeter=parallelogramPerimeter;...
```

Стиль із `perimeter=parallelogramPerimeter` ламає геометрію — draw.io малює
користувацькі точки ще й по периметру, і фігура виходить із битими діагоналями.
Завжди `perimeter=none` і задавай `spacingLeft` / `spacingRight` вручну.

### Експорт у PNG через браузер

Експорт через UI діалог прибирає можливість задати точний масштаб. Надійніше —
`convert.diagrams.net/export3.html`:

```
POST https://convert.diagrams.net/export3.html
  xml=<mxGraphModel XML>  format=png  scale=3  transparent=true
→ {"data": "<base64 PNG>"}
```

`transparent=true` дає прозорий фон, `scale=3` — print-grade. JPEG не вміє прозорість,
тому для JPEG блоки треба композит на білий.

## 📐 Довідник форм ГОСТ 19.701-90

| Елемент | Призначення | Форма |
| :--- | :--- | :--- |
| Термінатор | початок / кінець | прямокутник зі скругленням $r = h/2$ |
| Дані | введення / виведення | паралелограм зі зсувом бічних граней ~20 px |
| Процес | дія, присвоєння | прямокутник $1.5 : 1$ |
| Рішення | умова | ромб, виходи `Так` / `Ні` |
| Зумовлений процес | виклик підпрограми | прямокутник з двома внутрішніми вертикальними рисками |
| Підготовка | заголовок циклу-лічильника | витягнутий шестикутник |
| З'єднувач | перехід без перетину | коло 30–40 px з номером |

## ⚡ Елементи UML 2.5

- **Activity:** початковий вузол — заливний круг ~22 px; дія — прямокутник `rx=8`;
  fork/join — смуга 5–6 px; фінальний вузол — бичаче око.
- **Sequence:** прямокутники учасників, пунктирні лінії життя `4,4`, смуги
  активації 10 px, синхронний виклик — суцільна стрілка, відповідь — пунктирна.
- **Class:** три секції (назва / атрибути / методи), модифікатори `+ - #`,
  наслідування — суцільна з незафарбованим трикутником, реалізація — пунктирна.
