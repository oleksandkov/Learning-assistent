# Прототип 7. Генетичний канібалізм

## Статус і призначення

«Генетичний канібалізм» у цьому документі — авторська метафора агресивного генетичного алгоритму, а не усталена офіційна назва окремого методу. «Пожирання» означає вилучення корисного фрагмента ДНК невдалої хромосоми та перенесення його до сильнішої особини.

Мета прототипу — зберігати не тільки успішні маршрути. Якщо бот потрапив у тупик, початок його маршруту все одно міг бути корисним. Сильніший сусід забирає цей префікс, відкидає смертельну дію, змінює напрямок біля точки помилки та доповнює маршрут власними генами.

Усі назви «бот», «смерть», «поїдання» і «хижак» стосуються лише записів у пам’яті алгоритму.

## Представлення хромосоми

~~~cpp
struct CannibalChromosome {
    std::size_t id;
    std::vector<core::Direction> genes;
    std::vector<core::Direction> acceptedMoves;
    std::size_t validPrefix;
    std::optional<std::size_t> fatalGene;
    double fitness;
    bool won;
    bool deadlocked;
    int parentA;
    int parentB;
    int consumedId;
};
~~~

validPrefix — частина маршруту до першого критичного тупика. fatalGene — ген, після якого ящик став нерухомим або маршрут перестав покращуватися. Саме біля цієї точки виконується інверсія.

## Загальна схема

~~~mermaid
flowchart TD
    A[Створити популяцію ДНК] --> B[Запустити всіх ботів через GameRules]
    B --> C[Оцінити fitness і позначити тупики]
    C --> D[Сформувати локальні турніри]
    D --> E{Хто переміг?}
    E --> F[Сильний бот зберігає власну ДНК]
    E --> G[Невдалий бот віддає корисний префікс]
    F --> H[Схрестити префікс жертви з хвостом переможця]
    G --> H
    H --> I[Інвертувати або мутувати ген біля тупика]
    I --> J[Еліта + нові канібальні діти]
    J --> K{Розв’язок або ліміт поколінь?}
    K -- Ні --> B
    K -- Так --> L[ReplayValidator]
~~~

## Що означає «сусідній бот»

Сусідство не обов’язково географічне. Можливі три варіанти:

1. **Турнірне:** випадково вибрані 3–5 хромосом утворюють групу.
2. **За станом:** боти вважаються сусідами, якщо завершили маршрут зі схожими позиціями ящиків.
3. **За ДНК:** сусіди мають довгий спільний префікс генів.

Для першої реалізації достатньо турнірного сусідства: воно коротке, відтворюване з фіксованим seed і не потребує окремого індексу станів.

## Операція канібалізації

Нехай невдалий бот має:

~~~text
Жертва:     → → ↑ ↑ ← ↓ ...
                        × тупиковий ген
~~~

Сильний бот:

~~~text
Переможець: → ↑ → ↓ → → ...
~~~

Створюється дитина:

~~~text
1. Беремо безпечний префікс жертви:  → → ↑ ↑
2. Критичний ген ← не копіюємо.
3. Вставляємо альтернативу:          →
4. Додаємо хвіст переможця:          ↓ → → ...

Дитина:     → → ↑ ↑ → ↓ → → ...
~~~

Альтернативний ген вибирається серед допустимих напрямків, крім смертельного. Якщо альтернатив немає, префікс скорочується до попереднього штовхання.

## Fitness і правила «смерті»

Приклад оцінки:

~~~text
fitness =
    distanceToAssignedGoals × 35
    + acceptedMoves
    + invalidGenes × 3
    + repeatedStates × 8
    + stagnation × 20
    + deadlock × 1000
    - usefulPushes × 12
~~~

Бот оголошується невдалим, якщо:

- DeadlockDetector підтвердив незворотний тупик;
- протягом S генів не змінилась позиція жодного ящика;
- вичерпано ДНК без завершення рівня;
- надто багато генів відхилено GameRules.

Звичайний програш у турнірі не обов’язково означає «смерть»: частину слабких хромосом можна залишати для підтримання різноманітності.

## Примітивний псевдокод

~~~text
population = randomDNA(N, geneCount)
history = []

для generation в 1..G:
    для bot у population:
        trace = replayGenesThroughGameRules(bot.genes)
        bot.fitness = evaluate(trace)
        bot.fatalGene = detectFatalGene(trace)

    elites = найкращі E ботів
    groups = випадкові турніри
    children = []

    для group у groups:
        predator = найкращий у group
        victim = найгірший deadlocked/stagnant у group

        prefix = victim.genes до fatalGene
        escape = допустимий напрямок, відмінний від fatalGene
        tail = хвіст predator після випадкової точки
        child.genes = prefix + escape + tail
        локально мутувати гени біля місця з'єднання
        children.додати(child)

    population = elites + children + кілька випадкових новачків
    history.додати(population + genealogy)

повернути найкращий validated winner
~~~

## Приблизна інтеграція з програмою

~~~cpp
for (std::size_t generation = 0; generation < generationLimit; ++generation) {
    for (auto& bot : population) {
        evaluateThroughGameRules(board, initial, bot);
        bot.fatalGene = locateDeadlockOrStagnation(bot.trace);
    }

    std::sort(population.begin(), population.end(), byFitness);
    auto next = copyElites(population, eliteCount);

    while (next.size() < populationSize) {
        auto group = tournament(population, random);
        const auto& predator = best(group);
        const auto& victim = worstReusable(group);
        next.push_back(cannibalize(predator, victim, board, initial, random));
    }
    population = std::move(next);
}
~~~

cannibalize не може безпосередньо змінювати GameState. Вона створює нову ДНК, яку наступне покоління знову повністю програє через GameRules.

## Візуалізація у вебі

1. **Одночасний забіг.** Усі боти рухаються на спільній карті; лідер виділений, тупикові особини зупиняються.
2. **Турнірна арена.** Картки 3–5 учасників показують fitness, прогрес і причину вибування.
3. **Момент канібалізації.** ДНК жертви згасає, її корисний префікс переміщується до нової дитини, а критичний ген перекреслюється.
4. **Кольори походження.** Префікс жертви, альтернативний ген і хвіст переможця мають різні кольори.
5. **Родовід.** Клік по дитині показує predator, victim, точку тупика та місце з’єднання.
6. **Фільтр смертей.** Можна залишити на карті тільки deadlock, stagnation або invalid genes.
7. **Графік поколінь.** Окремо показуються найкращий fitness покоління, рекорд дотепер, кількість тупиків і генетичне різноманіття.

Анімація повинна бути навчальною, а не декоративною: користувач вручну запускає покоління, ставить паузу та переходить до конкретної хромосоми.

## Частота сканування поля

Парсер читає XSB один раз. Кожна хромосома програється з початкового GameState; поле повторно не сканується. Для популяції N, довжини ДНК L і G поколінь:

~~~text
оцінювання: O(G × N × L)
сортування: O(G × N log N)
пам’ять повної історії: O(G × N × L)
~~~

Для «тисяч ботів» не слід зберігати кожний кадр. Достатньо генів, прийнятих ходів, фінального стану, точки смерті та родоводу; проміжні позиції можна відтворювати локально.

## Лімітації прототипу 7

1. **Не є стандартним окремим алгоритмом.** Це спеціальна модифікація GA для навчального експерименту.
2. **Немає гарантії розв’язку або оптимальності.**
3. **Префікс жертви може бути оманливим.** Причина тупика іноді виникла значно раніше за останній ген.
4. **Інверсія одного ходу часто недостатня.** Для обходу перешкоди може знадобитися заміна цілого сегмента.
5. **Передчасна збіжність.** Сильні хижаки можуть швидко заповнити популяцію майже однаковою ДНК.
6. **Великі витрати.** Тисячі ботів із довгими генами дорого оцінювати й візуалізувати.
7. **Складна багатоящикова причинність.** Корисний початок для одного призначення ящиків може шкодити іншому.
8. **Чутливість до fitness.** Надмірний штраф за тупик відкине маршрути, які виглядають погано лише тимчасово.
9. **Величезна історія.** Потрібні прорідження, еліти, семпли та родовід замість повних кадрів усієї популяції.
10. **Валідація обов’язкова.** Переможна ДНК стає рішенням лише після ReplayValidator.

## Рекомендований мінімальний варіант

Почати з 64–128 хромосом, турнірів по чотири учасники, шести еліт і одного типу смерті — підтвердженого deadlock. Канібалізація повинна копіювати безпечний префікс, замінювати один критичний ген і додавати хвіст переможця. Тисячі ботів, просторове сусідство та складні інверсії варто додавати лише після вимірювання різноманіття і частоти реальних покращень.
