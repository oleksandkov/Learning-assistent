# Сокобан у браузері

Мінімалістичний український інтерфейс: меню, п’ять рівнів, генератор власних карт, ручна гра, BFS / A* Moves / A* Pushes, порівняння, перевірене відтворення та десять інтерактивних навчальних тем.

## Запуск

Потрібні Node.js 18.17+ та GCC із C++20. Для браузерних тестів рекомендовано актуальний Node.js LTS. На Windows скрипт автоматично знаходить GCC у PATH або стандартних каталогах MSYS2 (`ucrt64`, `mingw64`). Можна задати `CXX` повним шляхом до компілятора.

З кореня репозиторію:

```powershell
cd web
npm install
npm run dev
```

Відкрий http://localhost:3000. `predev` автоматично компілює C++ адаптер. Наступні запуски використовують готовий файл, якщо джерела ядра не змінилися. Emscripten для цього режиму не потрібен.

Production:

```powershell
npm run build
npm run start
```

Next.js використовує `.next-dev` для development і `.next` для production, щоб дві збірки не перезаписували кеш одна одної. Сервер запускається з каталогу `web`.

## Маршрути та керування

- `/`: три пункти «Грати», «Алгоритми», «Про гру»; коротка анімація один раз за вкладку.
- `/levels`: п’ять різних карт із `levels/` і перехід до власної карти, без копій XSB у TypeScript.
- `/levels/create`: процедурна карта 5-100 клітинок у кожному вимірі, 1-50 ящиків, стільки ж цілей, 0-20 точних внутрішніх стін і необов’язковий seed. Кожен результат розв’язується A* та перевіряється перед показом.
- `/play/[id]`: WASD / стрілки або екранні кнопки; U undo, Y redo, R restart; пробіл pause, N один крок replay. Клавіші української розкладки також працюють.
- `/play/custom`: остання створена в поточній вкладці карта з усіма можливостями звичайного рівня. Для полів понад 22 клітинки вмикається камера навколо гравця. Повноекранне вікно дозволяє вимкнути стеження, пересувати камеру та змінювати огляд від 7 × 7 до 41 × 41.
- `/about` та `/about/[id]`: BFS, A*, локальний BFS, reverse-push, Hungarian, deadlocks, hashing, replay, generation, parser/flood fill. Кожна тема має керовану демонстрацію, псевдокод і докладне пояснення.
- `/game-info`: історія з посиланням на офіційне джерело, правила та вигляд елементів поля. Невідомі сторінки мають справжню відповідь 404.

Третій слот використовує `03_two_boxes.xsb`: старий `03_microban_3.xsb` нерозв’язний. Його файл не змінено, він перевіряється в негативному тесті. Четвертий та п’ятий слоти використовують `04_warehouse.xsb` і `05_triple.xsb`. Старі ідентифікатори URL збережені.

## Єдине C++ ядро

`POST /api/game` передає XSB та історію команд до `bindings/web/native.cpp`. Адаптер використовує незмінні публічні API `LevelParser`, `GameSession`, `SolverRegistry`, `ReplayValidator`. Правила, BFS і A* не дублюються в TypeScript. Процес ізольований на запит, тому різні вкладки не ділять ігровий стан.

`POST /api/generate` викликає той самий C++ адаптер і `LevelGenerator`. Web-адаптер підбирає відтворюваний seed, для якого спільний генератор створює задану точну кількість внутрішніх стін. Рівень повертається лише після успішного A* розв’язання та `ReplayValidator`. Перевірений шлях зберігається разом із власною картою, тому «Шлях генератора» можна застосувати без нового пошуку. Це не окремий алгоритм, а вже знайдений під час генерації маршрут.

Пошук починається з поточної позиції. Порівняння запускає всі три алгоритми одночасно на однаковій історії. Час такого запуску залежить від конкуренції за CPU; для академічних вимірювань використовуй CLI benchmark. Кожне рішення зберігає власну початкову позицію, статистику й перевірений маршрут. Його можна застосувати, перерахувати або видалити окремо. Перезапуск рівня й ручні ходи зупиняють активне відтворення, але не видаляють рішення. Рішення та останній застосований алгоритм зберігаються для цієї карти в `sessionStorage`.

Познач два або три рішення й натисни «Порівняти вибрані поруч». Усі поля мають однакову початкову історію та спільні кнопки запуску, паузи, кроку вперед/назад і темпу. Кадри кожного такту отримуються через GameSession та показуються разом; коротший маршрут залишається у завершеному стані. Це синхронне відтворення рішень, а не візуалізація внутрішніх пошукових станів.

Візуальний дебаг має три етапи на ігровому полі: реальні стани, які solver дістає з фронтиру під час пошуку; покрокова побудова знайденого маршруту; анімований рух гравця з ящиками. Для BFS показано глибину й FIFO-чергу, для A* — фактичні `g`, `h` і `f = g + h`. Траса обмежена 160 станами, після чого пошук продовжується без накопичення кадрів. Кожен кадр готового маршруту повторно отримується через `GameSession`.

На великих картах камера спочатку слідкує за гравцем. Перетягування поля, `Shift` + стрілки або кнопки напрямків переводять її у вільний режим. Колесо миші та повзунок змінюють поле огляду; перемикач у повноекранному режимі повертає стеження за гравцем. Великий екран використовує бічну панель камери, а вузький автоматично переходить на нижню панель. Ігрове поле займає решту доступної площі.

Показується нативний `searchTime`, окремо preprocessing і reconstruction. Для звичайних карт пошук обмежено 8 секундами, 250 000 вузлами та налаштуванням 256 MiB ядра. Великі карти отримують до 30 секунд, 2 000 000 вузлів і 512 MiB; зовнішній watchdog власної карти працює 40 секунд. Обмеження залишаються запобіжником від зависання сервера, а гарантований шлях генератора не залежить від повторного пошуку. «Ліміт» відрізняється від «Немає рішення». Пам’яттєвий ліміт ядра є оцінкою, не OS-квотою. Навчальні анімації показують поле, хвилю дослідження, фронтир, відновлений маршрут і рух об’єктів. Це пояснювальні приклади, не трасування поточного solver. Для академічних вимірювань використовуй CLI benchmark із прогрівом та медіаною.

## Перевірки

```powershell
npm run typecheck
npm run test:native
npm run build
npx playwright install chromium
npm run test:e2e
```

Native-тести перевіряють усі 15 комбінацій «рівень × алгоритм», збіг BFS та A* Moves, replay, поточну позицію, заборонені ходи, нерозв’язний рівень, точні параметри генератора і межу 100 × 100. Playwright сам запускає production-сервер на 3105, перевіряє маршрути, керування, порівняння, replay, скасування, власну карту, камеру великого поля, навчальні кроки, мобільні розміри, темну тему й reduced motion. Знімки: `test-results/`.

## Межі поточної інтеграції

Потрібен Node.js сервер із нативним виконуваним файлом і каталогом `levels`. Це не статичний/offline WASM-застосунок; Emscripten/Web Worker залишається наступним етапом PLAN.md. Академічний benchmark доступний у CLI. Власна карта зберігається в `sessionStorage` поточної вкладки, а прогрес ходів скидається після перезавантаження. Авторизації немає; «вхід» означає відкриття меню.
