## 2. Постановка задачі

Розробити настільний програмний застосунок для автоматизації касового терміналу торговельної точки. Програма здійснює обробку кошика товарів покупця та формує деталізований фіскальний чек з урахуванням гнучкої системи знижок.

### Правила розрахунку (бізнес-логіка):
1. Користувач формує список з $N$ придбаних товарів (для кожного товару задається назва, ціна за одиницю та кількість).
2. **Індивідуальна знижка на товар:** Якщо ціна одиниці товару $P \ge 500{,}00$ грн (акційний/преміальний поріг $T_{item}$), на всю вартість даної позиції надається знижка $10\%$ ($Rate_{item} = 0{,}10$). Якщо поріг не досягнуто — знижка на товар становить $0\%$.
3. **Накопичувальна знижка чека:** Після підсумовування вартості всіх позицій (з урахуванням знижок на товари), перевіряється загальна сума $S_{after}$. Якщо $S_{after} \ge 1500{,}00$ грн (поріг лояльності $T_{receipt}$), клієнту надається знижка на чек $5\%$ ($Rate_{receipt} = 0{,}05$). В іншому випадку — $0\%$.
4. **Фінальні нарахування:** Обчислюється фінальна сума до сплати, виділяється ПДВ $20\%$ (включений у вартість: $VAT = S_{final} \cdot \frac{0.20}{1.20}$), підраховується сумарна зекономлена клієнтом сума та друкується касовий чек.

## 3. Виділення трьох основних ділянок алгоритму

Відповідно до теоретичних положень роботи, розроблений алгоритм містить усі три фундаментальні типи керуючих структур:

### 3.1. Лінійна ділянка (послідовне виконання дій)
У програмі наявні дві лінійні підділянки:
* **Початкова лінійна ділянка:**
  * Зчитування вхідних даних ($N$ товарів, граничні пороги знижок $T_{item}$, $T_{receipt}$).
  * Ініціалізація змінних-накопичувачів: `subtotal_raw = 0.0`, `total_item_discount = 0.0`, `subtotal_after_item = 0.0`, `i = 1`.
* **Фінальна лінійна ділянка:**
  * Розрахунок кінцевої вартості: `final_payable = subtotal_after_item - receipt_discount`.
  * Розрахунок сумарної вигоди клієнта: `total_saved = total_item_discount + receipt_discount`.
  * Розрахунок податку: `vat_amount = final_payable * (0.20 / 1.20)`.
  * Форматування та виведення результату у вигляд фіскального чека.

### 3.2. Циклічна ділянка (повторення операцій)
* Реалізована за допомогою циклу з лічильником: `for i in range(1, N + 1)` (або `for item in items`).
* Повторює обробку для кожного з $N$ товарів у списку.
* На кожній ітерації:
  1. Зчитується ціна та кількість $i$-го товару.
  2. Обчислюється базова вартість: $cost = price \cdot qty$.
  3. Накопичується базова сума: $subtotal\_raw = subtotal\_raw + cost$.
  4. Викликається розгалужена ділянка перевірки знижки товару.
  5. Накопичується сума знижок та проміжний підсумок.

### 3.3. Розгалужена ділянка (прийняття рішень, умовні оператори)
* **Розгалуження 1 (всередині циклу):**
  $$\text{Якщо } price \ge 500{,}00 \implies disc = cost \cdot 0{,}10; \quad \text{інакше } disc = 0{,}00.$$
* **Розгалуження 2 (після завершення циклу):**
  $$\text{Якщо } subtotal\_after\_item \ge 1500{,}00 \implies receipt\_disc = subtotal\_after \cdot 0{,}05; \quad \text{інакше } receipt\_disc = 0{,}00.$$

## 4. Представлення алгоритму у трьох виглядах

Згідно з вимогами лабораторної роботи (пункт 2 ходу роботи), алгоритм подано у трьох стандартизованих формах:

### Вигляд 1: Модель «Чорної» та «Білої» скриньки

#### Модель «Чорної скриньки» (Black Box)
Відображає відношення між входом і виходом системи без розкриття внутрішньої реалізації:

```
                  ┌─────────────────────────────────────┐
Вхідні дані       │                                     │ Вихідні дані
─────────────────>│          ЧОРНА СКРИНЬКА             ├─────────────────>
• Список товарів  │                                     │ • Деталізований чек
  (назва, ціна,   │ (Програмний алгоритм розрахунку     │ • Сума без знижок
  кількість)      │  касового чека та надання знижок)   │ • Знижка на товари
• Пороги знижок   │                                     │ • Знижка на чек
  (T_item, T_rec) │                                     │ • Підсумок ДО СПЛАТИ
                  │                                     │ • ПДВ (20%)
                  └─────────────────────────────────────┘
```

#### Модель «Білої скриньки» (White Box)

### Лістинг модуля `algorithm.py`:
```python
from dataclasses import dataclass
from typing import List, Dict, Any, Tuple

@dataclass
class ProductItem:
    name: str
    price: float
    quantity: int

    @property
    def cost_raw(self) -> float:
        return self.price * self.quantity

@dataclass
class ProcessedItem:
    name: str
    price: float
    quantity: int
    cost_raw: float
    discount_percent: float
    discount_amount: float
    final_cost: float

class ReceiptAlgorithm:
    def __init__(self, item_discount_threshold: float = 500.0,
                 item_discount_rate: float = 0.10,
                 receipt_discount_threshold: float = 1500.0,
                 receipt_discount_rate: float = 0.05,
                 vat_rate: float = 0.20):
        self.item_discount_threshold = item_discount_threshold
        self.item_discount_rate = item_discount_rate
        self.receipt_discount_threshold = receipt_discount_threshold
        self.receipt_discount_rate = receipt_discount_rate
        self.vat_rate = vat_rate

    def calculate(self, items: List[ProductItem]) -> Tuple[Dict[str, Any], List[str]]:
        trace_log = []

        # =========================================================================
        # 1. ЛІНІЙНА ДІЛЯНКА: ІНІЦІАЛІЗАЦІЯ
        # =========================================================================
        trace_log.append("[ЛІНІЙНА ДІЛЯНКА] Крок 1: Ініціалізація початкових змінних-накопичувачів.")
        subtotal_raw = 0.0
        total_item_discount = 0.0
        subtotal_after_item = 0.0
        processed_items: List[ProcessedItem] = []
        n = len(items)
        trace_log.append(f"[ЛІНІЙНА ДІЛЯНКА] Крок 2: Зчитано кількість позицій у чеку N = {n}.")

        # =========================================================================
        # 2. ЦИКЛІЧНА ДІЛЯНКА: ОБРОБКА ТОВАРІВ
        # =========================================================================
        trace_log.append(f"[ЦИКЛІЧНА ДІЛЯНКА] Вхід у цикл for i = 1..{n}.")
        for idx, item in enumerate(items, start=1):
            raw_cost = item.cost_raw
            subtotal_raw += raw_cost

            # =====================================================================
            # 3. РОЗГАЛУЖЕНА ДІЛЯНКА (А): ПЕРЕВІРКА ЗНИЖКИ НА ТОВАР
            # =====================================================================
            if item.price >= self.item_discount_threshold:
                disc_rate = self.item_discount_rate
                disc_val = raw_cost * disc_rate
                trace_log.append(f"  [РОЗГАЛУЖЕННЯ - ТАК] {item.name}: ціна {item.price:.2f} >= {self.item_discount_threshold:.2f}. Знижка 10%.")
            else:
                disc_rate = 0.0
                disc_val = 0.0
                trace_log.append(f"  [РОЗГАЛУЖЕННЯ - НІ] {item.name}: ціна {item.price:.2f} < {self.item_discount_threshold:.2f}. Без знижки.")

            item_final = raw_cost - disc_val
            total_item_discount += disc_val
            subtotal_after_item += item_final

            processed_items.append(ProcessedItem(
                name=item.name, price=item.price, quantity=item.quantity,
                cost_raw=raw_cost, discount_percent=disc_rate * 100,
                discount_amount=disc_val, final_cost=item_final
            ))

        # =========================================================================
        # 3. РОЗГАЛУЖЕНА ДІЛЯНКА (Б): ПЕРЕВІРКА ЗНИЖКИ НА ЧЕК
        # =========================================================================
        if subtotal_after_item >= self.receipt_discount_threshold:
            receipt_discount = subtotal_after_item * self.receipt_discount_rate
            receipt_discount_applied = True
            trace_log.append(f"[РОЗГАЛУЖЕННЯ - ТАК] Сума {subtotal_after_item:.2f} >= {self.receipt_discount_threshold:.2f}. Знижка на чек 5%.")
        else:
            receipt_discount = 0.0
            receipt_discount_applied = False
            trace_log.append(f"[РОЗГАЛУЖЕННЯ - НІ] Сума {subtotal_after_item:.2f} < {self.receipt_discount_threshold:.2f}. Знижка на чек 0%.")

        # =========================================================================
        # 1. ЛІНІЙНА ДІЛЯНКА (ФІНАЛ): ПІДСУМКОВІ РОЗРАХУНКИ
        # =========================================================================
        final_payable = subtotal_after_item - receipt_discount
        total_saved = total_item_discount + receipt_discount
        vat_amount = final_payable * (self.vat_rate / (1.0 + self.vat_rate))

        return {
            "processed_items": processed_items, "items_count": n,
            "subtotal_raw": subtotal_raw, "total_item_discount": total_item_discount,
            "subtotal_after_item": subtotal_after_item, "receipt_discount": receipt_discount,
            "receipt_discount_applied": receipt_discount_applied, "total_saved": total_saved,
            "final_payable": final_payable, "vat_amount": vat_amount
        }, trace_log
```

## 7. Відповіді на контрольні питання та завдання (стор. 8 методички)

1. **Охарактеризуйте алгоритм як чорну скриньку:**
   * У моделі «чорної скриньки» внутрішній устрій та алгоритмічні перетворення приховані від спостерігача. Відомими є виключно вхідні дані (вхід) та кінцевий результат роботи (вихід). Розглядається лише співвідношення між аргументами та функцією.
2. **Охарактеризуйте алгоритм як білу скриньку:**
   * У моделі «білої скриньки» відомі не лише вхід і вихід, але й точні правила обробки та перетворення інформації: внутрішні структури даних, послідовності обчислень, логічні зв'язки, відношення між елементами та алгоритмічні кроки.
3. **Дайте визначення обчислювального алгоритму:**
   * Обчислювальний алгоритм — це чітко визначена математична або обчислювальна процедура, на вхід якої подається набір величин або даних, і яка за скінченну кількість математичних та логічних кроків перетворює їх на шуканий числовий або структурний результат.
4. **Дайте визначення загального алгоритму:**
   * Загальний алгоритм — це високорівнева логічна послідовність кроків і взаємодій окремих підалгоритмів, модулів або підпрограм, спрямована на комплексну організацію процесу вирішення задачі (формування входу, виклик процедур обробки, візуалізація та виведення даних).
5. **Що таке дискретність інформації?**
   * Це властивість, яка полягає в тому, що кожний алгоритм оперує даними (вхідними, проміжними, вихідними), які подаються у вигляді окремих скінченних слів і символів деякого фіксованого алфавіту.
6. **Що таке дискретність роботи алгоритму?**
   * Це властивість алгоритмічного процесу розпадатися на окремі послідовні кроки (інструкції), при цьому на кожному кроці виконується строго одна елементарна операція.
7. **Що таке детермінованість алгоритму?**
   * Це властивість визначеності, згідно з якою система величин у кожен наступний момент часу однозначно визначається системою величин, отриманих на попередніх кроках, виключаючи довільне трактування дій виконавцем.
8. **Що таке елементарність кроків алгоритму?**
   * Вимога до простоти та локальності переходу між кроками: закон отримання кожної наступної величини з попередньої повинен бути елементарним, зрозумілим виконавцю і не потребувати додаткових роз'яснень.
9. **Що таке виконуваність операцій?**
   * Вимога відсутності в алгоритмі операцій, які виконавець не здатен здійснити (наприклад, неможливо присвоїти змінній значення «нескінченність» чи поділити на нуль). Кожна дія повинна мати чітке фізичне або машинне виконання.
10. **Що таке скінченність алгоритму?**
    * Вимога того, що як сам опис алгоритму має скінченний обсяг, так і його виконання для будь-яких коректних вхідних даних обов'язково завершується за скінченне число кроків з отриманням результату.
11. **Що таке спрямованість алгоритму?**
    * Властивість, яка гарантує, що у разі якщо спосіб отримання результату з деяких вхідних даних не призводить до стандартної відповіді, алгоритм повинен чітко визначати, що саме вважати результатом (наприклад, повідомлення про неможливість розв'язку або помилку).
12. **Що таке масовість алгоритму?**
    * Властивість алгоритму бути придатним для розв'язання не однієї одиничної задачі, а цілого класу однотипних задач з різними вхідними даними з потенційно нескінченної множини допустимих значень.
13. **Що таке карта Захмана (Zachman Framework)?**
    * Це класична матрична онтологія та архітектурна модель для опису складної структури підприємства (Enterprise Architecture), інформаційних систем і програмних продуктів з точки зору різних учасників розробки.
14. **На які питання відповідає заповнена карта Захмана?**
    * Вона відповідає на 6 фундаментальних базових запитань (стовпці матриці):
      1. **Що? (What)** — дані та інформаційні об'єкти;
      2. **Як? (How)** — функції та процеси перетворення;
      3. **Де? (Where)** — географія та мережеве розміщення;
      4. **Хто? (Who)** — користувачі, ролі та організація;
      5. **Коли? (When)** — час, події та життєві цикли;
      6. **Чому? (Why)** — цілі, бізнес-мотивація та правила.
15. **Які актори (діючі персонажі) представлені в карті Захмана?**
    * Рядки карти Захмана представляють погляди 5–6 ключових ролей (акторів):
      1. Планувальник (Scope / Planner / Context);
      2. Власник бізнесу (Business Model / Owner);
      3. Архітектор / Системний проектувальник (System Model / Designer);
      4. Розробник / Інженер (Technology Model / Builder);
      5. Інтегратор / Підрядник (Detailed Representations / Subcontractor);
      6. Користувач системи (Functioning Enterprise / User).
16. **Для якої архітектури використовується карта Захмана?**
    * Вона використовується для архітектури підприємства (Enterprise Architecture), архітектури корпоративних інформаційних систем (IS Architecture) та комплексного проектування складних IT-екосистем.

## 8. Відповіді на тестові питання та завдання (стор. 8–10 методички)

1. **Кожний алгоритм має справу з даними: вхідними, проміжними, вихідними. Ці дані представляються у вигляді скінченних слів деякого алфавіту, що характеризує:**  
   * **Правильна відповідь:** `дискретність інформації`.
2. **Початкова система величин може обиратись з деякої потенційно нескінченної множини, що характеризує:**  
   * **Правильна відповідь:** `масовість алгоритму`.
3. **Алгоритм виконується по кроках та при цьому на кожному кроці виконується тільки одна операція, що характеризує:**  
   * **Правильна відповідь:** `дискретність алгоритму` (дискретність роботи алгоритму).
4. **В алгоритмі не має бути не виконуваних операцій, що характеризує:**  
   * **Правильна відповідь:** `виконуваність алгоритму` (виконуваність операцій алгоритму).
5. **Якщо спосіб отримання наступної величини з деякої заданої величини не дає результату, то має бути вказано, що треба вважати результатом алгоритму, то це характеризує:**  
   * **Правильна відповідь:** `спрямованість алгоритму`.
6. **Закон отримання наступної системи величин з попередньої повинен бути простим та локальним, що характеризує:**  
   * **Правильна відповідь:** `елементарність кроків алгоритму`.
7. **Золоте правило розробника полягає:**  
   * **Правильна відповідь:** `дотримання всіх властивостей алгоритмів` та `використанні базових алгоритмів`.
8. **Алгоритми можуть бути представлені за різними формами, зокрема (вибрати правильні варіанти):**  
   * **Правильні відповіді (всі наведені у теоретичних відомостях форми):**
     1. описовий алгоритм — текстовий опис покрокового виконання поставленої задачі;
     2. у вигляді карт, схем, діаграм;
     3. у вигляді блок-схеми реалізації алгоритму;
     4. у вигляді псевдокоду;
     5. у вигляді лістингу мови програмування з коментарями до виконання;
     6. як математична модель;
     7. як візуальне представлення графу;
     8. як інструкція до виконання.
